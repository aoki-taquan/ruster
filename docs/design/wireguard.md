# WireGuard

状態: 2026-11-08、叩き台。mergeの前にownerの確認が要る。決まるまで、WireGuardのコードの変更は止める。

WireGuardを、FE、鍵交換、confdに分けて作るときの全体の設計。今まではFEのデータの処理から作り、
鍵とcounterの持ち主、再起動、鍵交換との分担を決めないまま進めた。そのため、見直しのたびに
同じ鍵とnonceで二度暗号化する経路が見つかった。この文書でそれを先に決める。

## 用語

- セッション: 一回のhandshakeでできる、送り用と受け用の鍵の組（whitepaperのkeypair）と、
  両側のindex。
- counter: 送るメッセージの番号。nonceになる。一つの送り鍵で同じcounterを二度使うと、
  ChaCha20-Poly1305の安全が壊れる。
- 窓: 受けたcounterの記録（RFC 6479）。再送されたメッセージを断るために使う。

## 守ること

1. 一つの送り鍵で、同じcounterを二度使わない。どのプロセスがいつ再起動しても守る。
2. 受けた鍵の窓が空に戻るときは、その受け鍵ももう使わない。
3. 秘密鍵とセッション鍵は、設定ファイル、ログ、エラー文、`state.sock`、Debugの表示に出さない。
4. 本物のWireGuard（Linuxのkernel、wireguard-go）と、MTUいっぱいのパケットまで通じる。

## 分担

| 仕事 | 置き場所 | 理由 |
|---|---|---|
| データの暗号化と復号、counter、窓、許すアドレスの照合 | FE | パケットごと |
| 送るときのセッションの選び方（今、前、次の三組） | FE | パケットごと |
| 期限の上限（Reject-After-Time 180秒、Reject-After-Messages） | FE | 越えたらパケットを止めるのはFE |
| handshake（Noise_IKpsk2）、cookie、再送、鍵の入れ替えの時計 | 鍵交換のプロセス | 相手と会話する。秘密鍵を持つ |
| ピア、公開鍵、endpoint、許すアドレスの設定 | confd | 設定 |
| keepalive（passiveとpersistent） | FE | 送ったり受けたりした時刻を知っているのはFE |
| endpointの追従（roaming） | FE（覚える）、鍵交換のプロセス（handshakeの宛先） | 認証が通ったパケットを見るのはFE |

秘密鍵は鍵交換のプロセスだけが持つ。FEとconfdは公開鍵とセッション鍵しか見ない。

### 鍵交換のプロセスを誰が作るか（ownerが決める）

charterの「作るもの」のCEは、confd、ribd、neighdだけで、鍵交換のプロセスは入っていない。
一方で、セッション鍵を外へ渡すWireGuardの実装は既製のものに無い（Linuxもwireguard-goも、鍵を
自分の中だけで使う）。そのため、どちらかを決める必要がある。

- A. rusterのrepositoryに鍵交換のプロセス（例: `ruster-wgd`）を作る。charterの「作るもの」に足す。
- B. 作らない。rusterは鍵を受ける口だけを持ち、外の誰かが作るのを待つ。それまでWireGuardは、
  試験の外では使えない。

この文書の残りは、どちらでも同じに書く。

## セッションの一生

```
鍵交換のプロセス                confd                       FE
  handshake完了 ─ セッション ─→ そのまま渡す ─────────────→ 受け取る（FEの起動番号を確かめる）
                                                             ├ 期限: 作った時刻 + 180秒
                                                             ├ 120秒、または counter が 2^60 を越えた → 「入れ替えが要る」
                                                             └ 送るときにセッションが無い → 「鍵交換が要る」
  ←───────── 通知（入れ替えが要る、鍵交換が要る、endpointが変わった） ──────────────┘
```

- セッションは、FEの起動ごとの番号（FEが起動時に乱数で決める。`state.sock`で読める）を持つ。
  FEは、自分の今の番号でないセッションを断る。
  - これで、FEが再起動したあとは、前のセッションがどの経路で届いても使われない。confdが
    再起動しても、鍵交換のプロセスが同じセッションを送り直しても、手で同じ鍵を書いても同じ。
  - FEが再起動すると、全部のピアがhandshakeからやり直しになる。Linuxでモジュールを読み直した
    ときと同じ。
  - counterをファイルに残す方法（前の案）はとらない。ファイルが壊れたり、別の機械へ移したり、
    書き込みが失敗したりしたときに、守ること1が崩れるため。
- セッションは作った時刻も持つ。FEは、受け取った時刻から180秒を過ぎたものを使わない
  （Reject-After-Time）。同じセッションの書き直しは、新しいセッションにならない。
- FEは、一つのピアについて三組まで持つ。
  - 今: 送るのに使う。
  - 前: 受けるのにだけ使う。入れ替えの直後に、相手が古い鍵で送ってきたものを受けるため。
  - 次: 応答側のhandshakeでできた組。相手からその鍵でデータが届いたら「今」に上げる。
  - 鍵交換のプロセスは、セッションが始め側（initiator）か応答側（responder）かを一緒に渡す。
- 二つのピアが同じ送り鍵や同じindexを持つ表は断る（今のとおり）。
- 鍵交換のプロセスが再起動したときは、FEは持っているセッションを期限まで使う。新しいセッションは
  前のものと違う鍵なので、counterの問題は無い。

## handshakeの通り道

- 待ち受けポートに来たtype 1〜3のメッセージ（handshakeとcookie）は、FEが受け渡しのsocketで
  鍵交換のプロセスへ渡す（`tables.md`の分類`wireguard-handshake`）。kernelには渡さない。
- 鍵交換のプロセスが送るhandshakeのメッセージも、受け渡しのsocketでFEへ渡し、FEが送る。
  そのため、待ち受けのアドレスとポートはFEが持つ一つだけになる。
- 流量の上限は分類ごとの上限（`tables.md`）で守る。多すぎるときのcookieは鍵交換のプロセスの仕事。

## endpointの追従

- whitepaper 2.1のとおり、認証が通ったデータの送り元へendpointを移す。
- 移したことは通知で鍵交換のプロセスへ伝える。次のhandshakeはそこへ送る。
- 設定のendpointは、最初に送る先としてだけ使う。

## 外側と内側

- 内側はIPv4とIPv6、外側もIPv4とIPv6。許すアドレスは両方の家族を持てる。
- 外側の経路は、インターフェースの「下側のVRF」（`tables.md`）で引く。今はdefaultだけ。
- 詰め物は`min(MTU, 16の倍数)`（Linuxと同じ）。受けるときは長さを確かめない。
- 外側はDFを付ける。DFの無い大きな内側パケットは、内側で分割してから一つずつ暗号化する。
- 外側のTOSはLinuxと同じ（DSCPは0、ECNはRFC 6040）。

## firewallとVRF

- 外側のパケット（UDP）は、開く前に、受けたインターフェースのVRFのinput firewallを通す。
- 開いた内側のパケットは、WireGuardのインターフェースに届いたものとして、そのVRFで扱う。
- WireGuardのインターフェースが消えたときに、内側のパケットが既定経路へ平文で出ないよう、
  そのインターフェースを向く経路は、インターフェースが無い間はdiscardとして残す。

## 表と通知

`tables.md`の`ruster-wireguard`を次のように直す。

| 表 / 通知 | 中身 | 書き手 / 受け手 |
|---|---|---|
| インターフェース | 待ち受けポート、下側のVRF、自分の公開鍵 | confd |
| ピア | 公開鍵（キー）、endpoint、許すアドレス、persistent keepalive | confd |
| セッション | ピア、送り鍵、受け鍵、両側のindex、FEの起動番号、作った時刻、始め側か応答側か | 鍵交換のプロセス（confdは通すだけ） |
| 状態（読むだけ） | FEの起動番号、ピアごとの今のendpoint、最後のhandshakeとデータの時刻、数 | FE |
| 通知 | 鍵交換が要る、入れ替えが要る、endpointが変わった | FE → confd → 鍵交換のプロセス |

ピアのキーは名前ではなく公開鍵にする（WireGuardの設定と同じ）。

## 今のコードとの差

作ったもの（#471〜#487）のうち、データの暗号化と復号、窓、外側のIPv4、FEの表の組み立て、
confdの設定のピアとインターフェースは、そのまま使う。次は作り直すか足す。

- セッションに起動番号と作った時刻を足す。FEの「使った鍵の指紋」のファイルは作らない（#487の続きの案はとらない）。
- 鍵を三組持つ。期限、入れ替えの通知、keepalive、roaming。
- handshakeを受け渡しのsocketで鍵交換のプロセスへ渡す。
- IPv6、下側のVRF、DFの無い大きなパケット、外側のfirewall、消えたインターフェースの経路。
- ピアのキーを公開鍵にする。

## 試験

- 鍵交換のプロセスができたら、netnsでLinuxのkernelのWireGuard（`ip link add type wireguard`と
  `wg`）とつなぐ。handshake、鍵の入れ替え、MTUいっぱい、roaming、FE / confd / 鍵交換の
  プロセスの再起動を、両方向で確かめる。
- それまでは、今のnetnsの試験（OpenSSLの対向）とe2eで、データの処理と守ること1〜3を確かめる。
