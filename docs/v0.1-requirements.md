# ruster v0.1 要件定義

## 1. 目的

`ruster` v0.1 は、自宅ラボで実用可能なソフトウェアルータをフルスクラッチで成立させる最初のマイルストーンである。  
特に、L2/L3転送と NAT を含む基本機能を実装し、10GbE 環境で「普通に使える」状態を目標とする。

## 2. 前提とターゲット

- 利用環境: 自宅ラボ
- データプレーン基盤: DPDK を主軸に採用
- 性能評価の初期条件: 1500B パケット中心
- 目標体感: NAT込みでも 10GbE 回線を実用できること

## 3. 設計境界

- 必須: ネットワークのパケット処理コアは完全自作
- 必須: パケット解析処理は自作
- 許容: 暗号、CLI、周辺管理機能は外部依存可
- 方針: 独自プロトコルは原則導入しない

## 4. 機能要件（Must）

### 4.1 L2

- MAC学習
- MACテーブル管理（学習、参照、エージング）
- ARP処理（要求/応答、キャッシュ管理）
- L2転送処理

### 4.2 L3

- IPv4 ルーティングテーブル管理
- 最長一致前方一致に基づく転送
- 隣接解決と転送連携（ARP連携）

### 4.3 NAT（家庭用で普通に使う機能を包含）

- 動的NAPT（PAT）
- 静的ポートフォワード
- Hairpin NAT
- コネクショントラッキング（タイムアウト管理）
- NATと整合する最小の stateful フィルタ

### 4.4 設定・運用

- 宣言ファイル `router.toml` を基準設定として扱う
- 暗黙デフォルト禁止（挙動が設定から読める）
- `validate -> plan -> apply` を必須フローとする
- 稼働中変更は許可し、未反映差分として保持できる
- 自動ロールバックは任意機能（v0.1必須外）

## 5. 非機能要件

- 実用安定性: 長時間運転で転送停止やメモリリークが発生しない
- 可観測性: 最低限の統計情報とエラーカウンタを取得できる
- 再現性: 同一設定で同一挙動を再現できる

## 6. 非スコープ（v0.1ではやらない）

- OSPF/BGP 等の動的ルーティングプロトコル
- SRv6 uSID 実装
- 64B 線速達成を前提とした極端な最適化
- 大規模ISP向け高度機能

## 7. 受け入れ基準（初期）

- L2/L3/NAT の基本処理が統合動作する
- 家庭用想定トラフィックで通信が継続し、破綻しない
- 1500B 条件で 10GbE を実用できる性能傾向を示す
- 設定変更フローが `validate -> plan -> apply` で一貫して動作する

## 8. 将来拡張

- 動的ルーティングを段階的に追加
- SRv6 uSID を含む新規プロトコル対応
- 性能評価指標の厳格化（IMIX、64B、小遅延評価）
