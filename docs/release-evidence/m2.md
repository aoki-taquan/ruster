# M2 release evidence: Operable AF_XDP static router（M2a）

M2のexit criteria（[development plan](../development-plan-v0.2.md#m2-operable-af_xdp-static-router)）
ごとの判定と証跡を記録する。M1と同じく、判定はevidence、ready SHA、CI URLで行い、PR数では
行わない。証跡を示せないものは`unverified`と書く。

**結論: M2全体はcloseしていない。M2aのscopeは完了した。** M2a/M2bの分割はcoordinating agentの
scoping提案で、owner決定ではない。

- **M2a**（このfileが閉じる範囲）: `ruster run`の下で動くcopy-mode AF_XDP router、veth E2Eを
  CIで実行する。multi-queue、zero-copy、X05を含まない。
- **M2b**（残り）: multi-queue（S12）、zero-copy、X05 lab evidence。owner決定（2026-11-02）で
  deferred: 2a「C」（当面portごとに1 queue、X05のNIC選定と合わせて再検討）、X05 labは当面不要で
  運用はveth（実NIC/native/zero-copy未検証のriskはownerが受け入れた）。

9 criterionのうち、M2aで**met**が7（1、2、3、5、6、7、9）、**partially met**が1（4）、
**not met**が1（8、X05）である。partially metの残りとnot metはすべてM2bか、下の「M2aに含まない
もの」に記したdeferred/open項目である。criterion 5と9は当初partially metで、下の「M2a gap fill」
（#305）のveth E2Eでmetにした（veth/netnsでの実行で、hardware labでは実行していない点は従来どおり）。M2a closing SHAは、このfileを追加したPRの`main`への

**見つけたproduct bugと修正（CLI-052）**: health watchの`KICK_ERRORS`入力が`ENETDOWN`のkickも数えていた。
watch（`crates/cli/src/run/watch.rs`）、runbook §7、CLI-052は「`ENETDOWN`以外」と定めるが、
`crates/cli/src/run/linux.rs`はengineの`kick_errors`（失敗したkickすべて）をそのまま渡していた。
link downのportにTXがin flightだとsettleのたびにkickが`ENETDOWN`で失敗するので、`LINK_DOWN`に加えて
`warning: port=if2 health=KICK_ERRORS`、`--kick-errors-fatal-secs`（既定5 s）後に
`fatal: port=if2 health=KICK_ERRORS`でexit 1になっていた（再現: 修正前のbinaryでtxfull phaseが
`txfull: exited while the TX ring was full`でfailする）。#305はadapterの`kicks_link_down`を引く
（`watched_kick_errors`、unit test `enetdown_kicks_are_not_kick_errors_for_the_watch`）。#302の
link down phaseはTXがin flightでない時のdownなので、このbugを踏まなかった。
