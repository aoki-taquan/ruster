### 2. M1 golden scenario through public full composition（met、FW-025はtracked deviation）

`fixtures/m1/scenario.toml`を`SimIo`上の`run_tick`＋`ActivePublication`で実行する（#278）。
test `m1_golden_scenario_passes_and_matches_golden_output`（SIM-010）が全`expect`の成功と
`fixtures/m1/expected.jsonl`とのbyte一致を確認する。golden出力は70行（start 1、inject 18、
tick 20、tx 14、apply 5、expect 11、final 1）。

coverage: LAN/WAN static route、ARP Request生成→Reply学習→学習MACで転送（dynamic ARP）、
UDP/TCP SNATとreply de-NAT、FW rule allowとdeny、NAT mapping miss、TTL 1→Time Exceeded
Type 11/Code 0、応答しないconnected hostへARP 3回→Destination Unreachable Type 3/Code 1、
route miss→Destination Unreachable Type 3/Code 0（step 7b、v2のegress `Any` rule 40が許可）。
v1（egress限定ruleだけ）のroute missはsilentな`FIREWALL_ROUTE_UNAVAILABLE`のまま。

route-miss ICMP: ownerはRFC準拠を基準とする決定（2026-11-01）を行い、#284（`9990f58`）を
mergeした。firewall有効時のroute missは、どのegressへも新規flowとして許可されegress依存の
NAT gateにも当たらないpacketにだけ、firewallなしと同じ経路でType 3/Code 0を生成する
（FW-025 `route_miss_permitted_toward_every_egress_generates_the_plain_type3_code0`、
ICMP4-012G）。#285（`c256e92`）はrouter-originated ICMPv4の4 class（Echo Reply、Time Exceeded、
Network/Host Unreachable）にRFC動作をdefaultとするswitchを追加した（ICMP4-002B、
ICMP4-012J〜J4。`every_generation_class_defaults_to_rfc_behavior`ほか
`crates/io-sim/tests/icmpv4_generation_switches.rs`）。fixture v1は全switchを`true`で明示し、
golden出力は`final` eventへ0値の4 keyが増えた以外byte不変である。

**tracked deviation（FW-025）**: route撤去後の既存flowのpacket（established TCP ACK、egress
限定allowのUDP等）はsilentで、RFC 1812 §5.2.7.1のType 3/Code 0を返さない。#285で再評価し
deviationを維持した。routeはconfig publicationでしか変わらず、全publicationは新generationと
FW hash key rotationで全flowをflushするため、route missの時点で参照できるestablished stateは
存在しない。同じreload後にrouteが残っていてもそのpacketはsilentにdropされるので、route missだけ
answerするとroute oracleになる（`withdrawn_route_flow_is_flushed_so_route_hit_and_miss_stay_equally_silent`）。
解消にはflowを保ったままrouteを変えるpublication（動的routing等）が必要で、そのsliceで再検討する。
operatorはegress `Any`のallow ruleと`net-unreachable` switchで挙動を選べる。criterion 2の
scenario要件（route ICMPを含む）はgoldenのstep 7bで満たしており、このdeviationはclose条件ではない。


### 5. reload / restart-required / rollback（met）

- reloadは`run_tick`先頭のpublication phaseだけで行う（RT-001〜003、PUB-006）。
- restart-required: storage shape、Resolution/ICMPv4 policy、interface IfId/MAC変更を
  `RestartRequired`でreject（PUB-003 `successor_checks_generation_keys_shape_and_fixed_policies_without_apply`、
  PUB-008 `plan_restart_classification_matches_live_apply_rejection`）。
- rollback: 旧config文書を再validateし、新generation・新keyでapply
  （PUB-009 `rollback_reapplies_old_document_as_new_generation_with_new_keys`）。
- golden: step 28でv2をgeneration 2としてapplyしflush数を出力、step 38 `STORAGE_SHAPE`、
  step 39 `INTERFACES`をrestart-requiredでreject（candidate generation 3、4は消費）、step 43で
  v1をgeneration 5として再apply。

### 6. SIGINT/SIGTERM ordered shutdown（met）

`--hold`はscenario後もidle tickを続ける。signal handlerはstatic `AtomicBool`へstoreするだけで、
CLIはtick境界で停止→backend quiescence（未完了batch、live lease、未完了TXなし）を確認→
`final` eventを書いてexit 0。tests: `hold_mode_shuts_down_in_order_on_sigterm`（CLI-006）、
`hold_mode_shuts_down_in_order_on_sigint`（CLI-007）。

```bash
cargo build --locked -p ruster-cli
d=$(mktemp -d)
target/debug/ruster run-sim --scenario fixtures/m1/scenario.toml --hold > "$d/hold.jsonl" 2> "$d/hold.err" &
pid=$!; sleep 1; kill -TERM "$pid"; wait "$pid"; echo "exit=$?"
tail -n 1 "$d/hold.jsonl" | cut -c1-60
cat "$d/hold.err"
```

期待: `exit=0`、最終行が`{"event":"final",...,"generation":5,...`、stderrが
`holding at generation 5`と`stopped by signal ... generation 5`。`at_ms`とtick数はsleep時間に
依存する。job controlのないshellで`&`起動するとSIGINTはignoreを継承するため、手動確認には
SIGTERMを使う（SIGINTはCLI-007がprocess spawnで確認する）。
