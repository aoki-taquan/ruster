# ruster v0.1 実装 Issue 一覧

この文書は、別Agentにそのまま割り振れるように、v0.1実装を Issue 単位へ分解したもの。  
各 Issue は「受け入れ条件」を満たしたらクローズできる。

## マイルストーン

- M1: 起動基盤と設定基盤（I-001 から I-004）
- M2: L2/L3 データプレーン（I-005 から I-008）
- M3: NAT/FW（I-009 から I-011）
- M4: 運用性と検証（I-012 から I-014）

## I-001 [P0] Rust ワークスペース初期化とcrate分割

### 目的

実装を並列化しやすい最小構成を作る。

### 実装内容

- Rust workspace を作成する。
- 最低限の crate を分割する（例）:
- `config`（設定ロード/検証）
- `control`（validate/plan/apply）
- `dataplane`（転送処理）
- `observe`（統計/可観測）
- `main`（エントリポイント）
- 共通エラー型とログ初期化を定義する。

### 受け入れ条件

- `cargo build --workspace` が通る。
- crate 間依存が循環しない。
- `README.md` に crate 役割が追記される。

### 依存

- なし

## I-002 [P0] DPDK 起動基盤（EAL/ポート/キュー初期化）

### 目的

v0.1 のデータプレーン前提である DPDK backend を最小成立させる。

### 実装内容

- `router.toml` の `[dataplane]` / `[[interfaces]]` から起動パラメータを読み込む。
- EAL 初期化、mempool 初期化、port init、RX/TX queue init を実装する。
- `admin_up=true` な IF のみ起動する。
- 起動失敗時に原因が分かるエラーメッセージを返す。

### 受け入れ条件

- 2ポート構成で DPDK 初期化完了まで到達する。
- 設定不備時に fail-fast する（panic禁止、明示エラー）。

### 依存

- I-001

## I-003 [P0] `router.toml` strict ローダ/スキーマ検証

### 目的

暗黙挙動なしの設定モデルを実装する。

### 実装内容

- `docs/router-toml-schema-v0.1.md` に対応する `serde` 構造体を作る。
- 未知キーをエラーにする strict deserialize を実装する。
- 必須キー欠落、列挙値不正、参照整合性不正を検出する。
- 最小バリデーション規則をすべて実装する。

### 受け入れ条件

- `router.toml.example` が validate 成功する。
- 不正設定ケースの単体テストを作る。
- バリデーションエラーにキー名と理由が含まれる。

### 依存

- I-001

## I-004 [P0] 設定フロー `validate -> plan -> apply` 実装

### 目的

運用時の安全な変更フローを成立させる。

### 実装内容

- running/candidate/pending 差分のモデルを実装する。
- `validate` コマンド: 構文/意味検証のみ実施。
- `plan` コマンド: 変更差分を表示（追加/削除/変更）。
- `apply` コマンド: 設定反映を実施。
- ランタイム変更を pending として保持し、明示 commit で基準設定へ反映する。

### 受け入れ条件

- no-op 変更時に「変更なし」を返す。
- 不正差分は apply 前にブロックされる。
- `validate -> plan -> apply` の統合テストが通る。

### 依存

- I-003

## I-005 [P0] パケット解析基盤（Ethernet/ARP/IPv4/TCP/UDP/ICMP）

### 目的

L2/L3/NAT/FW が共通利用できるパケット解析層を作る。

### 実装内容

- 最低限のヘッダパーサを自作する。
- 解析結果を保持する packet metadata 構造体を定義する。
- 不正パケットの drop 理由コードを統一する。
- パーサ単体テストを用意する。

### 受け入れ条件

- 正常/異常ケースを含むテストが通る。
- 後段が metadata だけで判定可能な構造になる。

### 依存

- I-001
- I-002

## I-006 [P0] L2 ブリッジング + MAC 学習/エージング

### 目的

v0.1 Must の L2 転送要件を満たす。

### 実装内容

- IF を `l2_domain` 単位でブリッジする。
- 宛先MAC学習、FDB参照、unknown unicast flood を実装する。
- `mac_aging_sec` に従うエージング処理を実装する。
- ループ回避のため同一受信IFへの再送を禁止する。

### 受け入れ条件

- 同一L2ドメイン内で双方向通信できる。
- FDB 学習/エージングが観測できる。

### 依存

- I-002
- I-005

## I-007 [P0] ARP/隣接キャッシュ処理

### 目的

L2/L3 連携の前提となる隣接解決を成立させる。

### 実装内容

- ARP request/reply 処理を実装する。
- ARP キャッシュ参照/更新/タイムアウトを実装する。
- next-hop 未解決時の解決フローを実装する。
- gratuitous ARP を受信時更新対象として扱う。

### 受け入れ条件

- L3転送時に ARP 解決経由で送信できる。
- `arp_timeout_sec` が機能する。

### 依存

- I-005
- I-006

## I-008 [P0] IPv4 静的ルーティング + L3 転送

### 目的

v0.1 Must の L3 転送要件を満たす。

### 実装内容

- 静的ルートテーブルをロードする。
- 最長一致検索で next-hop/out_if を決定する。
- TTL 減算、ヘッダ更新、転送判定を実装する。
- 直結ネットワーク宛と経路宛の分岐を実装する。

### 受け入れ条件

- デフォルトルート経由で WAN へ転送できる。
- ルート未一致は drop + counter 増加となる。

### 依存

- I-005
- I-007

## I-009 [P0] Conntrack エンジン（NAT/FW共通）

### 目的

NAT と stateful FW の共通状態管理を実装する。

### 実装内容

- 5-tuple ベースのセッション管理を実装する。
- TCP/UDP/ICMP の状態・タイムアウトを実装する。
- タイムアウト掃除処理（GC）を実装する。
- セッション上限超過時の動作（drop + log/counter）を定義する。

### 受け入れ条件

- timeout パラメータが設定値どおり反映される。
- セッション作成/更新/削除が統計で観測できる。

### 依存

- I-005
- I-008

## I-010 [P0] NAT44（NAPT + Port Forward + Hairpin）

### 目的

家庭用ルータ相当の NAT 機能を v0.1 で成立させる。

### 実装内容

- outbound NAPT（PAT）を実装する。
- inbound 静的 port forward を実装する。
- hairpin NAT を実装する。
- 変換前後で checksum を正しく更新する。

### 受け入れ条件

- LAN -> WAN の同時多接続が成立する。
- WAN -> LAN のポートフォワードが動作する。
- LAN から WAN 側アドレス経由で内部サーバへ hairpin 接続できる。

### 依存

- I-009

## I-011 [P0] 最小 stateful Firewall 実装

### 目的

NAT と整合する最低限のフィルタ制御を実装する。

### 実装内容

- chain (`input` / `forward` / `output`) を実装する。
- default policy と rule 評価順を実装する。
- `allow_established_related` 判定を実装する。
- zone (`wan` / `lan` / `any`) 条件を実装する。

### 受け入れ条件

- `router.toml.example` の rule で期待どおり通信制御できる。
- 既存セッション返り通信が許可される。

### 依存

- I-009
- I-010

## I-012 [P1] 可観測性（counter/stat/理由コード）

### 目的

検証とデバッグが可能な最小運用情報を提供する。

### 実装内容

- IF 単位の RX/TX/drop counter を実装する。
- L2/L3/NAT/FW 各段の drop reason counter を実装する。
- MAC/ARP/conntrack テーブルの件数/状態を取得可能にする。
- text ベースの `show` 相当 API/CLI を実装する。

### 受け入れ条件

- 問題発生時に「どこで落ちたか」を counter で追える。
- 主要テーブルの使用率を確認できる。

### 依存

- I-006
- I-011

## I-013 [P1] E2E 機能検証シナリオ（家庭用ルータ想定）

### 目的

v0.1 受け入れ基準を自動で確認できるようにする。

### 実装内容

- 最低限の E2E 検証シナリオを作る:
- L2 通信シナリオ
- L3 静的ルーティング通信シナリオ
- NAT outbound シナリオ
- Port Forward シナリオ
- Hairpin NAT シナリオ
- FW の許可/拒否シナリオ
- 再現性のあるテスト実行手順を文書化する。

### 受け入れ条件

- シナリオを連続実行して同一結果になる。
- 失敗時に原因箇所を counter で特定できる。

### 依存

- I-012

## I-014 [P1] 性能検証（1500B・NAT込み・10GbE実用）

### 目的

v0.1 の性能目標に対する到達度を測定する。

### 実装内容

- 1500B 条件の測定手順を作る。
- NAT有効時の throughput / loss / latency を計測する。
- ボトルネック観測（CPUコア、queue、table hit率）を行う。
- 結果をレポート化し、次の最適化候補を列挙する。

### 受け入れ条件

- 再実行可能な手順で数値を再取得できる。
- 「家庭用で実用か否か」を判断できる材料が揃う。

### 依存

- I-013
